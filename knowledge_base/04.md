# Testare il primo stadio

Questa sarà una lezione relativamente breve che ci porterà a verificare quanto il primo stadio del bootloader che abbiamo già scritto funzioni. Per farlo, scriveremo un secondo stadio molto semplice che stampa solamente un messaggio di uscita, messaggio che comunque manterremo anche nella forma **definitiva** del secondo stadio per informare l'utente di quello che sta avvenendo.

Dentro a `bootloader_st2.asm` scriviamo il seguente codice:

```nasm
bits 16
org 0x7E00

start:
    xor ax, ax
    mov ds, ax
    mov si, message

.print:
    lodsb
    test al, al
    jz .halt

    mov ah, 0x0E
    mov bx, 0x0007
    int 0x10
    jmp .print

.halt:
    cli
    hlt
    jmp .halt

message:
    db "Stage 2 loaded!", 0
```

Quindi andiamo ad assemblare i due sorgenti:

```sh
$ nasm -f bin bootloader_st1.asm -o stage1.bin
$ nasm -f bin bootloader_st2.asm -o stage2.bin
```

A questo punto usiamo `dd`, che ci permette di copiare, per creare l'immagine e inserire i due binari appena generati:

```sh
$ dd if=/dev/zero of=rabboot.img bs=512 count=2880
$ dd if=stage1.bin of=rabboot.img bs=512 count=1 conv=notrunc
$ dd if=stage2.bin of=rabboot.img bs=512 seek=1 conv=notrunc
```

`if` sta per **input file** ed è un file speciale fornito dai sistemi Linux che genera un flusso infinito di byte nulli (`0x00`). `of` sta invece per **output file**, ovvero dove deve copiare gli 0 dell'`if`. Se non esiste, **la** crea.

Poi gli diciamo di copiare 2880 blocchi di dimensione (`bs`, che sta per **block size**) pari a 512 byte. Questo genera un'immagine riempita di 0 di dimensione 1.44 MB, ovvero la capacità standard dei floppy, anche se con un floppy il sorgente che abbiamo scritto *non* andrebbe bene in quanto le `13H` Extensions non sono utilizzabili.

Quindi copiamo un blocco da 512 byte dallo stage1 e lo mettiamo nell'immagine. `conv=notrunc` obbliga a non troncare il file, evitando di perdere la dimensione originale dell'immagine. La stessa cosa **si** fa nella copiatura del secondo stage. `seek=1` ci permette di saltare 1 blocco nel file di destinazione prima di iniziare a scrivere.

Questi comandi, per quanto semplici, vengono lasciati in un file bash `generate_image.sh`.

Una volta generata, possiamo osservare la nostra creatura in byte con `hexdump`:

```sh
$ hexdump rabboot.img
```
